# FLAVO — Food Research Workspace

식품 중소기업의 해외진출·현지화 리서치를 위한 **기업별 구독 워크스페이스**입니다. 한국어·영어로 근거가 연결된 보고서와 Q&A를 제공하며, 제공된 로고·고운바탕·한식 일러스트를 유지합니다.

현재 버전은 단일 서버에서 운영하는 초기 SaaS 구현입니다. 계정·기업 분리, 영속 작업 큐, 사용량 제한, Stripe Checkout/Portal/웹훅, 메일 인증과 팀 초대를 포함합니다. **실제 고객 결제·이메일·외부 배포는 운영 설정과 검증 후 활성화**해야 합니다. 운영 준비와 제한은 [배포 안내](deploy/OPERATIONS.md)를 확인하세요.

## 공개 데모

**[FLAVO 웹사이트 열기](https://jellyfish040918.github.io/food_report/)**

GitHub Pages에서는 로그인 없이 실제 집계 데이터, 세계지도·그래프, 데이터 출처와 한국어·영어 샘플 보고서를 볼 수 있습니다. 샘플은 브라우저에서 집계와 고정된 계획 틀로 구성하며 AI를 호출하거나 회사 정보를 수집·저장하지 않습니다. AI Q&A·기업 계정·구독·영속 보고서는 아래의 서비스 서버가 필요합니다. 공개 데모를 실제 SaaS 서비스로 표시하지 않습니다.

`python scripts/build.py --pages`는 별도의 `dist-pages/`에 API 호출 없는 공개 화면만 빌드합니다. `main`의 테스트와 운영 컨테이너 검사가 통과하면 GitHub Actions가 Pages에 게시합니다. 일반 `python scripts/build.py`와 Docker는 기존 SaaS 앱을 빌드합니다. 원본 자료·계정 DB·비밀 설정은 두 빌드 모두 제외됩니다.

## 로컬 실행

Python 3.13, Node.js 22 이상, 설치된 Ollama와 `qwen3.5:9b`가 필요합니다. 브라우저에는 엔진 브랜드나 모델 선택기를 표시하지 않습니다.

```powershell
cd C:\flavo
.\start.ps1
```

[로컬 워크스페이스](http://127.0.0.1:4175/)를 엽니다. 최초 실행에는 Python 의존성 설치가 있습니다. 이미 설치된 모델은 재사용합니다. 모델 준비를 건너뛰고 데이터 요약만 확인하려면 `.\start.ps1 -SkipAI`를 실행하세요. 포트는 `-Port 4180`으로 바꿉니다.

이미 환경이 준비된 경우:

```powershell
.venv\Scripts\python.exe scripts/build.py
.venv\Scripts\python.exe serve.py --port 4175
```

개발 모드는 루프백 주소에만 연결하며 **FLAVO Studio 데모 워크스페이스**에 자동 진입합니다. 로그인·가입 화면은 `/#login`으로 열 수 있습니다. 개발 모드 가입은 메일 인증 없이 테스트할 수 있지만 실제 운영 모드는 인증을 요구합니다. 운영 DB에 개발 DB를 복사하지 마세요.

## 사용 흐름

1. **에이전트 홈**에서 목표, 제품, 시장을 정합니다. 전략 보고서와 근거 Q&A를 선택합니다.
2. **작업 현황**에서 실제 서버 단계, 대기·실패·완료 기록을 확인합니다. 브라우저를 닫아도 작업이 계속되며 취소·재시도가 가능합니다.
3. **전략 보고서**에서 관측 사실, 세계지도·표·그래프, 현지화 가설, 90일 실행 계획을 읽고 검토 완료를 표시합니다. PDF는 브라우저 인쇄로, Markdown은 다운로드로 내보냅니다.
4. **데이터 Q&A**는 집계 근거를 조회한 뒤 모델로 설명을 작성합니다. 모델 또는 응답 검증 실패 시 데이터 직접 답변을 명시하며 사용량을 차감하지 않습니다.
5. **팀·구독 관리**에서 사용량, 팀 초대·접근 해제, 워크스페이스 전환, Stripe 구독 관리와 운영 기록을 확인합니다.

새 보고서와 질문은 기업별 서버 DB에 저장합니다. 이전 `flavo.reports` 브라우저 자료는 개발 모드에서만 ‘이 기기 보관’으로 함께 보여 주며 원본을 삭제하거나 서버로 자동 업로드하지 않습니다. 운영 모드에서는 해당 기기의 과거 자료를 노출하지 않습니다.

한국어/EN 전환은 화면과 **새로 생성하는 결과**의 언어를 바꿉니다. 기존 보고서는 원문을 보존합니다. 이전 질문 최대 6개를 문맥에 사용할 수 있으나 이전 AI 답변을 사실의 근거로 사용하지 않습니다. 임의 원본 행 검색·실시간 웹 검색·요청 기간별 재집계는 제공하지 않습니다.

## 에이전트와 운영 구조

```text
브라우저 → 동일 출처 API → 로그인·기업 권한·사용량 확인
                            ↓
                       SQLite 영속 대기열
                            ↓
           요청 확인 → 서버 근거 조회 → 모델 초안 작성
                            ↓
           형식·근거 번호 검사 → 보고서 구성 → 기업별 저장
                            ↓
                        담당자 최종 검토
```

수치는 `src/engine.mjs`와 `qa.py`가 집계 파일에서 계산합니다. 보고서 API가 브라우저에서 만들어 보낸 근거·모델명·기업 ID를 신뢰하지 않습니다. 보고서 문장 전체의 사실 일치 여부를 자동 보증하는 시스템은 아니며 모델 제안은 검증할 가설로 읽어야 합니다.

현재 구성은 **도구를 사용하는 단일 오케스트레이터**입니다. 여러 독립 AI가 토론하거나 자율 웹 검색을 수행하는 구조는 아닙니다. 분석용 `qwen3.5:9b`가 문장을 작성하고, 코드로 작성한 데이터 도구가 수치·그래프·조회 범위를 담당합니다. 코드 생성 모델을 고객 요청마다 실행하지 않습니다. 웹의 **에이전트 안내**에서 보고서/Q&A별 다섯 단계와 각 단계의 입력·출력·한계를 확인할 수 있습니다.

새 결과는 `backend/provenance.py`가 작성한 분석 기록을 포함합니다. 이 기록은 작업 ID, 스냅샷 날짜, 조회 근거와 참조 근거 수, 항목별 출처 연결, 근거 묶음의 SHA-256, 검사 시각을 보관합니다. 해시는 같은 근거 묶음을 식별하기 위한 값이며 사실 정확성이나 외부 기관 인증을 뜻하지 않습니다. 응답 형식과 해당 작업에 실제 존재하는 출처 ID만 자동 검사하며, 의미·최신성은 담당자 검토 대상으로 표시합니다. 이전 결과에 검사 기록을 소급해 만들어 붙이지 않습니다.

보고서의 최초 검토자와 검토 시각은 서버에 저장하고 표시합니다. 같은 검토 요청을 다시 보내도 최초 기록을 덮어쓰거나 중복 감사 로그를 만들지 않습니다. 결과는 `분석과 검토 기록`을 펼쳐 확인할 수 있습니다.

- `backend/auth.py`: Argon2 비밀번호, 세션 쿠키, CSRF, 인증·재설정 메일과 일회용 토큰.
- `backend/store.py`: 기업·멤버·작업·결과·검토·사용량·운영 기록, 원자적 작업 예약.
- `backend/agent.py`: 근거 도구, 모델 호출, 실제 단계 기록, 취소, 응답 검증.
- `backend/provenance.py`: 실행별 출처 연결 검사와 재현 가능한 근거 식별 기록.
- `backend/billing.py`: 서버 지정 Price ID, Checkout/Portal, 서명 검증, 구독 상태 동기화.
- `backend/app.py`: 동일 출처 FastAPI, 접근 권한과 요청 제한, 정적 화면 제공.
- `src/service.mjs`, `src/account.mjs`, `src/saas.css`: 세션, 작업 현황, 팀·구독·로그인 화면.
- `src/agent.mjs`, `src/views.mjs`, `src/chat.mjs`: 목표 입력, 보고서·시장 탐색, 근거 Q&A.
- `src/method.mjs`, `src/studio.css`: 한국어/영어 단계 안내, 분석 기록, 서체와 시각 체계.
- `src/figures.mjs`, `src/geo/world.json`: 오프라인 세계지도·시계열·분포·비교표.
- `scripts/report_worker.mjs`: 서버와 화면이 공유하는 통계·보고서 엔진 실행.
- `serve.py`: 현재 서비스 진입점. `server.py`는 기존 모델 계약/테스트 지원 코드이며 직접 실행해도 `serve.py`로 연결합니다.

무료 체험은 14일/5회/1명, Starter는 월 30회/3명, Team은 월 100회/10명입니다. 실제 가격·통화는 Stripe에 등록한 Price로 정하며 코드에 임의 가격을 넣지 않았습니다. 월 한도는 UTC 매월 1일 기준입니다. 완료된 보고서·AI 답변과 대기/실행 중 작업이 한도에 포함됩니다. 실패·취소·AI 미사용 Q&A는 예약을 반환합니다.

세계지도는 [Natural Earth 공개 도메인 경계](https://www.naturalearthdata.com/downloads/110m-cultural-vectors/)를 사용합니다. 상대 검색지수이며 매출·절대 수요 지도가 아닙니다. 제목은 그리운 예은(GeuriunYeeun), 짧은 안내는 이서윤체(IsYun), 긴 본문은 고운바탕을 사용합니다. 작은 UI·표·수치는 시스템 서체로 가독성을 유지합니다. 웹폰트는 사용자가 지정한 jsDelivr 주소에서 `font-display: swap`으로 불러오며 연결 실패 시 대체 서체로 표시합니다.

공용 서비스의 초기 운영은 현재 단일 서버 구성으로 시작할 수 있지만, 동시 처리 확대가 필요하면 PostgreSQL, 별도 영속 큐, 독립 모델 워커로 분리하는 단계가 필요합니다. 그때도 인증·기업 권한·원자적 사용량 예약·중복 방지·취소·분석 기록 계약을 유지해야 합니다. 공개 출시 전 Stripe 실결제, 메일, HTTPS, 백업 복구와 데이터·이미지·서체 사용권 확인 사항은 [운영 안내](deploy/OPERATIONS.md)에 정리되어 있습니다.

## 데이터와 계산 방법

`python scripts/prepare_data.py`는 원본 파일에서 `src/generated/data.json`을 재생성합니다. 표준 라이브러리만 사용하며 대용량 CSV는 스트리밍으로 읽습니다.

| 데이터 | 사용 범위 | 집계 |
| --- | --- | ---: |
| Google Trends | 9개 검색어·5개 채널, 시계열·지역·검색어 | CSV 148개 |
| Food.com Recipes | `recipes.csv` 전체 레시피·제품군·재료 집계 | 522,517건 |
| Food.com Reviews | `reviews.csv` 전체 평점·키워드·레시피 ID 연결 | 1,401,982건 |
| Recipe Ingredients | `train.json` 요리 분류별 재료 등장률 | 39,774건 |
| Restaurant Reviews | `train.csv` 영어 키워드 리뷰 등장 수 | 102,582건 |
| FlavorSense | 취향 값의 전체 표본 분포 | 10,000건 |

- 검색 변화율 = `(최근 완결 12개월 평균 / 직전 12개월 평균 - 1) × 100`.
- 현재 스냅샷 비교 기간: 2025.10–2026.09 대 2024.10–2025.09. 진행 중인 2026년 10월은 그래프와 비교에서 제외합니다.
- 0인 관측값이 절반을 넘거나 기준 기간 평균이 0이면 성장률을 만들지 않습니다. 0은 검색량 부족일 수 있습니다.
- 떡볶이 원본 검색어가 `tteokbboki`입니다. 경고를 표시하고 성장 판단에 사용하지 않습니다.
- 별도로 수집한 검색어의 0–100 지수는 절대 검색량처럼 비교할 수 없습니다. 지역 값은 각 지역의 전체 검색 대비 정규화된 비중이며 매출·시장 규모가 아닙니다.
- 한식 관련 레시피 749건은 Name·RecipeCategory·Keywords의 `korean, kimchi, bulgogi, japchae, tteokbokki, bibimbap` 매칭 결과입니다.
- 국가와 직접 대응하는 요리 분류가 없으면 없는 것으로 표시합니다. 미국 재료 표본은 남부 요리로 제한합니다.
- Food.com 전체 CSV 2개를 순회합니다. RecipeId로 리뷰 1,401,963건을 연결하고, 연결되지 않은 19건은 전체 집계에만 포함합니다. RecipeId·ReviewId 중복은 현재 원본에 없으며 추후 중복 유입 시 ID별 1건만 집계합니다.
- CSV/Parquet 행 수가 같고, 레시피의 ID·이름·분류·집계 평점·리뷰 수 및 리뷰의 ID·RecipeId·Rating·Review 전체 순서별 내용 해시가 일치함을 확인했습니다. 대체 저장 형식인 Parquet를 별도 표본으로 더하지 않습니다.
- 9개 제품군을 Name·RecipeCategory·Keywords의 영어 정규식으로 선택합니다. 규칙은 `scripts/foodcom.py`와 집계 JSON의 `foodcom.matching`에 공개됩니다. 별칭이 누락될 수 있고, 제품군은 서로 중복될 수 있어 합산하지 않습니다. 떡은 mochi 등 타국 쌀떡도 포함합니다.
- 예: 김치 레시피 115건 → 리뷰 195건 → 유효 평점 184건, 평균 4.65/5. 리뷰당 키워드를 1회 집계하며, 평점 0·결측·범위 밖 값은 평균에서 제외합니다. 리뷰가 없는 떡볶이를 전체 리뷰로 대체하지 않습니다.
- Food.com 리뷰 작성 시점은 2000–2020년입니다. 과거 플랫폼 표본이며 최신 판매 실적·특정 국가 선호로 해석하지 않습니다. 리뷰 원문·작성자 정보는 공개 집계 파일과 모델 입력에서 제외합니다.
- Restaurant Reviews 테스트셋·중복 사본·ZIP는 별도 표본으로 미포함입니다.
- 리뷰의 단어 등장은 감성 분석이 아닙니다. FlavorSense는 수집 지역·시점·표본 설계가 없어 국가별 맛 선호 판단에 사용하지 않습니다.
- 경쟁사 매출, 시장 규모, 관세, 인증과 수입 규정은 제공 데이터에 없습니다. 모델에게 만들어내지 않도록 지시하고 별도 확인 사항으로 남깁니다.
- 집계 스냅샷에는 원문 리뷰나 개인 작성자 정보가 들어가지 않습니다. `data/`와 대용량 원본은 Git에서 제외됩니다.

새로운 기간의 원본으로 갱신할 경우 `prepare_data.py`의 부분 월 기준과 스냅샷 날짜도 함께 변경해야 합니다. 자동 실시간 수집 서비스는 아닙니다.

## Railway와 공개 홈페이지

GitHub Pages는 제품 소개·AI 채팅/보고서 진입 메뉴·데이터 샘플을 제공합니다. 실제 AI 분석은 별도 Railway 서버에서 로그인 후 실행합니다. [Railway 배포 안내](deploy/RAILWAY.md)에 월 $10 한도의 비공개 테스트 구성, 모델 이미지, 영속 저장소와 정식 SaaS 전환 조건을 정리했습니다. 테스트 계정 비밀번호는 호스팅 서비스의 Variables에만 입력합니다.

## 실행과 배포 검증

```powershell
node --test tests/*.test.mjs
.venv\Scripts\python.exe scripts/build.py
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

자동 검증은 실제 집계 자료와 임시 DB, 통제된 모델·Stripe 응답을 사용합니다. GPU·실제 카드 결제를 실행하지 않습니다. 실제 결제와 SMTP 전송은 각 운영 계정의 테스트 환경에서 별도로 확인해야 합니다.

저장소는 [jellyfish040918/food_report](https://github.com/jellyfish040918/food_report)입니다. 2026-10-11 [GitHub Actions 릴리스 검사](https://github.com/jellyfish040918/food_report/actions/runs/38130602078)에서 테스트 76개, 웹 빌드, Linux Docker 이미지 빌드와 격리된 운영 모드 기동·접근 권한·데이터 도구 검사가 통과했습니다. **이 버전은 서버 계정과 작업 큐가 필요하므로 GitHub Pages 단독 배포 대상이 아닙니다.** 고객용 서버는 아직 배포하지 않았으며, 포함된 Docker/Caddy 구성을 운영 환경에서 설정해야 합니다. 전체 Compose의 HTTPS·모델·외부 결제·메일 실연동은 별도 검증이 필요합니다. 자세한 명령, Stripe 설정, 백업·복구와 출시 점검은 [운영 안내](deploy/OPERATIONS.md)에 있습니다.
